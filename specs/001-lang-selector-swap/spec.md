# Feature Specification: 語系選擇器與互換功能

**Feature Branch**: `001-lang-selector-swap`  
**Created**: 2026-04-28  
**Status**: Draft  
**Input**: 使用者描述：「請追加讓我可以在設定檔中開啟此功能（語系選擇），然後界面的部份預計在前端視窗能有原語系選擇 <--> 目的語系選擇，中間的 <--> 可點擊後互換」

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 管理員透過設定檔啟用語系選擇器 (Priority: P1)

管理員希望可以在不修改程式碼的情況下，透過編輯設定檔（`config.yaml`）控制是否顯示語系選擇器 UI。當功能關閉時，介面維持現有的自動偵測行為；當功能開啟時，介面顯示語系選擇器列。

**Why this priority**: 這是整個功能的開關控制，沒有此機制，語系選擇器 UI 就無法在不同部署環境中彈性開關。

**Independent Test**: 在 `config.yaml` 中將 `features.language_selector` 設為 `true`，重新啟動服務，前端應出現語系選擇器列；設為 `false` 後重啟，語系選擇器列應消失且行為回到自動偵測。

**Acceptance Scenarios**:

1. **Given** `config.yaml` 中 `features.language_selector: false`，**When** 使用者開啟翻譯頁面，**Then** 頁面不顯示語系選擇器，翻譯行為維持自動偵測語系。
2. **Given** `config.yaml` 中 `features.language_selector: true`，**When** 使用者開啟翻譯頁面，**Then** 頁面顯示「原語系選擇 ↔ 目的語系選擇」列。
3. **Given** 設定檔中未定義 `features.language_selector`，**When** 服務啟動，**Then** 行為等同 `false`（預設關閉，向下相容）。

---

### User Story 2 - 使用者手動選擇原語系與目的語系 (Priority: P1)

語系選擇器啟用後，使用者可以在翻譯前從下拉選單中指定「原語系」與「目的語系」，取代原本的自動偵測。

**Why this priority**: 這是語系選擇器 UI 的核心功能，無此功能則整個 UI 無意義。

**Independent Test**: 啟用語系選擇器後，分別選擇原語系「英文」與目的語系「繁體中文」，輸入英文文字並送出翻譯，後端應收到 `source_lang: "en"` 與 `target_lang: "zh-TW"`。

**Acceptance Scenarios**:

1. **Given** 語系選擇器已啟用，**When** 使用者從原語系下拉選單選擇某語系，**Then** 所選語系顯示於選單中且翻譯請求攜帶對應的 `source_lang`。
2. **Given** 語系選擇器已啟用，**When** 使用者從目的語系下拉選單選擇某語系，**Then** 所選語系顯示於選單中且翻譯請求攜帶對應的 `target_lang`。
3. **Given** 語系選擇器已啟用且使用者未手動變更選擇，**When** 使用者送出翻譯，**Then** 原語系與目的語系均以「自動偵測」送出，後端依輸入文字內容自動推導語系（`source_lang: null`、`target_lang: null`）。

---

### User Story 3 - 使用者點擊互換按鈕交換原語系與目的語系 (Priority: P2)

在語系選擇器列的中間有一個可點擊的互換按鈕（`↔`），點擊後原語系與目的語系的選擇值互換，方便使用者快速切換翻譯方向。

**Why this priority**: 互換功能是提升操作效率的輔助功能，核心翻譯流程不依賴它。

**Independent Test**: 選擇原語系「繁體中文」、目的語系「英文」，點擊 `↔` 按鈕後，原語系應變為「英文」，目的語系應變為「繁體中文」。

**Acceptance Scenarios**:

1. **Given** 原語系為「繁體中文」、目的語系為「英文」，**When** 使用者點擊 `↔` 按鈕，**Then** 原語系變為「英文」、目的語系變為「繁體中文」。
2. **Given** 原語系為「自動偵測」、目的語系為「英文」，**When** 使用者點擊 `↔` 按鈕，**Then** 互換後原語系變為「英文」、目的語系變為「自動偵測」。
3. **Given** 使用者完成互換，**When** 立即送出翻譯，**Then** 翻譯請求應使用互換後的語系值。

---

### Edge Cases

- 若後端 `GET /api/languages` 回傳空清單或請求失敗，前端應隱藏整個語系選擇器列，頁面以自動偵測模式正常運作，不顯示錯誤訊息干擾使用者。
- 語系清單載入進行中時，兩個語系選擇器必須呈現停用狀態並顯示載入中指示（如 spinner 或骨架佔位符），禁止使用者互動直到載入完成。
- 當使用者手動將原語系切換為某一明確語系時，若目的語系與新選擇的原語系相同（或仍為「自動偵測」），系統應自動推薦對應的目的語系；具體規則：選中文 → 目的語系自動切為英文，選英文 → 目的語系自動切為繁體中文。（目前僅支援 zh-TW 與 en 兩種語系，未來新增語系時此規則需重新定義。）
- 原語系與目的語系選擇相同語系時，送出翻譯前應顯示警告提示，告知使用者原語系與目的語系相同。
- 設定檔格式錯誤（例如 `features.language_selector` 非布林值）時，服務啟動應視同 `false` 並記錄警告訊息，不中斷服務。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統必須支援在 `config.yaml` 的 `features` 區塊中新增 `language_selector` 布林旗標，用以控制是否啟用語系選擇器 UI。
- **FR-002**: 當 `features.language_selector` 為 `false` 或未設定時，前端介面不得顯示語系選擇器，翻譯行為維持原有自動偵測邏輯。
- **FR-003**: 當 `features.language_selector` 為 `true` 時，前端翻譯頁面必須在輸入區域上方顯示「原語系選擇器 ↔ 目的語系選擇器」列。
- **FR-004**: 語系選擇器的可選語系清單必須從後端 `GET /api/languages` 動態取得（僅包含真實語系，不含「自動偵測」）；前端在清單頭部自行插入「自動偵測」選項（代碼 `null`）；原語系選擇器與目的語系選擇器的初始預設值均為「自動偵測」。若 `GET /api/languages` 失敗，前端必須隱藏整個語系選擇器列，頁面以自動偵測模式運作。
- **FR-005**: 使用者選擇語系後，翻譯請求必須將所選語系以 `source_lang` 與 `target_lang` 欄位傳送至後端；任一選擇器選擇「自動偵測」時，對應欄位傳 `null`，由後端自動推導。
- **FR-006**: 原語系選擇器與目的語系選擇器之間必須有一個可點擊的互換按鈕（`↔`），點擊後兩個選擇器的值純粹互換；互換動作**不觸發** FR-009 的自動切換邏輯。
- **FR-009**: 當使用者變更任一語系選擇器時，若另一側語系為「自動偵測」或與剛選擇的語系相同，系統必須自動切換另一側至對應語系：
  - 選繁體中文（`zh-TW`）→ 另一側自動切換為英文（`en`）
  - 選英文（`en`）→ 另一側自動切換為繁體中文（`zh-TW`）
  - 兩側均為「自動偵測」時不觸發。
  - 此規則對原語系與目的語系選擇器均適用（雙向）。
  - 互換動作不觸發此規則。
- **FR-007**: 後端必須擴充現有 `GET /api/config` endpoint，回傳包含 `features.language_selector` 布林值的 JSON 結構；前端在頁面初始化時呼叫此 endpoint 取得旗標值，不得將旗標硬寫於前端程式碼中。
- **FR-008**: 原語系與目的語系均選擇了**相同的明確語系**（非「自動偵測」）時，系統必須在語系選擇器列附近顯示 inline 警告提示；送出翻譯按鈕仍可點擊，使用者可自行決定是否繼續。兩者皆為「自動偵測」時不觸發警告。
- **FR-010**: 語系選擇器啟用且語系清單尚未載入完成時，兩個語系選擇器必須呈現停用狀態並顯示載入中指示；載入完成後自動啟用，使用者在此期間不得與選擇器互動。
- **FR-011**: `GET /api/config` 請求失敗時，前端必須回退為 `language_selector: false`，不顯示語系選擇器列，頁面以原有自動偵測模式正常運作；不得因 config 載入失敗而阻斷翻譯主功能。

### Key Entities

- **AppConfig（應用程式設定）**: 代表 `config.yaml` 中 `features` 區塊的設定，包含 `language_selector: bool` 旗標；由後端在啟動時讀取，並透過 API 暴露給前端。
- **LanguageOption（語系選項）**: 目前僅支援兩種真實語系：繁體中文（`zh-TW`）與英文（`en`）；另包含由前端插入的特殊選項「自動偵測」（代碼 `null`）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 管理員修改 `config.yaml` 並重啟服務後，語系選擇器 UI 的顯示或隱藏與設定值完全一致，成功率 100%。
- **SC-002**: 使用者在語系選擇器啟用時手動選擇語系，後端收到的 `source_lang` / `target_lang` 與選擇值完全相符，無誤差。
- **SC-003**: 使用者點擊 ↔ 互換按鈕後，兩個選擇器的值立即互換，操作反應時間在 200 毫秒以內（視覺無延遲感）。
- **SC-006**: 使用者切換原語系至中文或英文後，目的語系自動切換的反應時間在 100 毫秒以內（即時反應，無需額外操作）。
- **SC-004**: 語系清單載入失敗時，頁面其餘翻譯功能（自動偵測模式）仍可正常使用，不出現全頁錯誤。
- **SC-005**: 在語系選擇器啟用的情況下，使用者完成一次完整的「選語系 → 輸入文字 → 送出 → 獲得翻譯結果」流程，所需步驟不超過 4 個操作。

## Clarifications

### Session 2026-04-28

- Q: 互換按鈕（`↔`）點擊後，FR-009 的自動切換邏輯是否仍觸發？ → A: 否，互換後不觸發 FR-009，兩側值純粹交換；FR-009 僅在使用者主動操作下拉選單時觸發。
- Q: 前端取得 `features.language_selector` 旗標的方式？ → A: 後端**擴充現有** `GET /api/config` endpoint，回傳 `{ "features": { "language_selector": true } }`。
- Q: 語系清單載入中時語系選擇器的顯示狀態？ → A: 顯示停用狀態的佔位符（disabled + 載入中指示），載入完成後啟用。
- Q: 原語系與目的語系相同時，警告行為是阻止送出還是僅顯示警告？ → A: 僅顯示警告提示，送出按鈕仍可點擊。
- Q: `GET /api/config` 載入失敗時前端的回退行為？ → A: 預設 `language_selector: false`，不顯示語系選擇器，頁面以自動偵測模式正常運作。

### Session 2026-04-28（第二輪）

- Q: `GET /api/languages` 回傳清單中是否包含「自動偵測」選項？ → A: 否，後端只回傳真實語系；「自動偵測」由前端在清單頭部自行插入，代碼為 `null`。
- Q: 目前支援的語系範圍？ → A: 目前僅支援繁體中文（`zh-TW`）與英文（`en`）互翻。
- Q: `GET /api/languages` 失敗時的錯誤提示形式？ → A: 整個語系選擇器列隱藏，頁面以自動偵測模式運作（與 config 失敗相同處理）。

## Assumptions

- 目前服務僅支援繁體中文（`zh-TW`）與英文（`en`）互翻；`GET /api/languages` 回傳清單將只包含此兩種語系。
- 後端已存在 `GET /api/languages` endpoint，回傳真實可用語系清單（不含「自動偵測」）；前端負責在清單頭部插入「自動偵測」選項並將其代碼對應為 `null`。
- 前端已存在 `LanguageSelector.razor` 元件與 `LanguageService.cs`，此功能僅需整合，不需從零建立。
- `config.yaml` 的 `features` 區塊為新增區段；現有部署若無此區塊，預設行為維持不變（向下相容）。
- 前端透過後端 `GET /api/config` endpoint 取得 `features.language_selector` 旗標值；此 endpoint 為現有 endpoint 的擴充，在既有 `max_input_length` 欄位基礎上新增 `features` 欄位，具向下相容性。
- 語系選擇器啟用時，原語系與目的語系選擇器的初始值均為「自動偵測」，以保留原有便利性並降低使用者的操作門檻；使用者可隨時手動切換為明確語系。
